# 跑通与基准示例（对齐私有化知识口径）

知识文档把基准分成两类，**不要混成一个综合分**：

| 类型 | 测什么 | 本仓库怎么做 |
|------|--------|--------------|
| **推理服务测速（Serving）** | TTFT、tokens/s、显存、并发 | 需自建 vLLM/SGLang + GPU；本 Demo 走 DashScope，**不做完整 Serving 报告** |
| **任务质量（RAG/Task）** | 答对没有、关键词/支撑 | 用 `kb/product_faq.md` 小标注集 + `scripts/run_rag_smoke_bench.py` |

概念验证建议：先任务冒烟（本脚本）+ 并发=1 的端到端时延；签约前再上客户同款机器做 Serving。

## 1. 界面跑通（真人点一点）

1. 启动：`python app.py` 或 Render 公网。  
2. 模式选 **固定知识库**，问：「这份知识库支持哪些文件类型？」  
3. 右侧 **高级设置** 可改 `max_ref_token` / 检索器 → **应用设置** → 清空对话 → 再问。  
4. 切 **灵活知识库**，上传任意 PDF/MD，问摘要。  
5. 看状态行：**上次端到端 ≈ xx ms（并发=1）**。

## 2. 一键冒烟基准（脚本）

```powershell
cd 仓库根目录
.\.venv\Scripts\Activate.ps1
# 确保 DASHSCOPE_API_KEY 可用
python scripts\run_rag_smoke_bench.py
```

输出：

- 每题 `PASS/FAIL`（回答是否含期望关键词）  
- `keyword_hit_rate`、`e2e_p50` / `e2e_mean`  
- JSON：`workspace/bench_last.json`

**声明：** `keyword_hit_rate` 只是无完整标注集时的**代理指标**，不要写成合同里的召回率%。

## 3. 和文档指标的对应

| 文档指标 | 本 Demo |
|----------|---------|
| TTFT / TPOT / GPU 显存 | 未测（无自建推理栈） |
| 端到端时延、并发=1 | 脚本 + 界面状态行 |
| Hit@K / Recall@K | 未接检索日志导出；用关键词命中代理 |
| 完整 Serving 压测 | 另建 vLLM 环境后按知识文档清单做 |
